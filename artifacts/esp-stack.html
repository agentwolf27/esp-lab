Orientation

Five layers, and they compose

ESP's tools aren't 44 separate projects. They're a stack: a data layer feeding encoders, encoders feeding task heads, and a language model sitting on top — each layer independently usable. Read it bottom-up.

The one to start with

AVEX

One load_model() call gets you BEATs, EAT, EfficientNet, AVES, BirdAVES, BirdNET or Perch 2 with a shared embedding API. The ICLR 2026 paper behind it is a systematic study of what actually makes a good bioacoustic encoder — the winner is SSL pre-training then supervised post-training on bioacoustics plus AudioSet.

runs local~90M params
The headline model

NatureLM-audio

The first audio-language model for animal sounds. You prompt it in English — “What is the common name for the focal species?” — and it answers, including for species it has never heard. Watkins marine mammals: 0.788 vs 0.257 for the next best model.

24 GB GPU8.7B params
The unlock for small teams

DRASDIC

Few-shot detection trained entirely on 8,800 hours of synthetic domain-randomised scenes. Label ~30 seconds of one call type, and it finds every other instance in your recordings with no fine-tuning. Beats training-free methods by 64% relative on the 13-task FASD13 benchmark.

runs localzero training

alp-data

Thirty-four datasets — Xeno-canto, iNaturalist, Watkins, BirdSet, AnimalSpeak, plus specialist sets for gibbons, geladas, giant otters, marmosets, killer whales and individual-ID tasks — all behind one class with consistent resampling, labels and streaming. Released July 2026.

Research

What the papers actually established

Twenty-two publications, and a clear arc: build encoders, benchmark them honestly, then put language on top. The results below are the ones that change what we should build.

ICLR 2026 · foundation

AVEX: what matters for animal vocalization encoding

A 26-dataset study of encoder recipes. Best result comes from SSL pre-training followed by supervised post-training on bioacoustics plus AudioSet — BEANS classification 0.840, beating BirdNET and Perch. Notably, the tiny EfficientNet-B0 wins on individual ID (0.531) and repertoire tasks (0.582), so bigger is not automatically better.

weights releasedarXiv 2508.11845
ICASSP 2026 · method

Multi-layer attentive probing

How you read an encoder changes which encoder looks best. Swapping the standard last-layer linear probe for a multi-layer attention probe adds ~0.08 accuracy on BEANS classification and detection, and reorders the leaderboard. The probe has ~1–2 M parameters and trains in minutes on cached embeddings.

highest leverage for us
ICLR 2025 · foundation

NatureLM-audio

Transfer from human speech and music into bioacoustics genuinely works. Zero-shot on unseen species by taxonomic name: 0.343 versus 0.014 for CLAP. Call type 0.871, life stage 0.794, captioning SPIDEr 0.532 versus 0.009 for the nearest audio-LLM.

needs a GPUarXiv 2411.07186
2025 · detection

Voxaboxen & DRASDIC

Two complementary detectors. Voxaboxen predicts onset/offset boxes and stays accurate through overlap — 97.9 mAP on overlapping zebra finch audio versus 78.3 for a frame-based BEATs baseline. DRASDIC needs no training data at all: 8,800 hours of synthetic scenes taught it to generalise from a 30-second example.

both usable now
DCASE 2025 · surprising

Crossing the species divide

Frozen human-speech models (WavLM, HuBERT, XEUS) with nothing but a linear probe rival fine-tuned bioacoustic models on BEANS — Watkins 0.90, dogs 0.95. This is the cheapest strong baseline in the entire field, and it runs on a laptop.

reproduce this first
2024–2025 · signal

Biodenoising & ISPA

Biodenoising trains a denoiser with no clean recordings at all, using speech-enhancement pseudo-targets; ~9 dB SI-SDR improvement, and the 19 M-parameter model denoises faster than real time on CPU. ISPA turns calls into readable token strings so ordinary text models can classify them.

both run local

Also worth knowing

  • BAGEL (2026) — 11,852 multiple-choice questions probing animal knowledge in LLMs. Frontier models reach 0.76; the hardest category is describing vocalizations (0.59). A cheap regression test.
  • BEBE (Movement Ecology 2024) — on bio-logger accelerometer data, a self-supervised model trained on human wrist data wins 9 of 9 datasets when training data is scarce.
  • Carrion crows (Animal Cognition 2025) — 127,750 calls detected at F1 0.78; most crow communication turns out to be quiet, close-range family talk that microphones on trees never capture.
  • Bee dance (Biological Reviews 2026) — argues the waggle dance is an ancestral iconic semantic system, with a phylogenetic reconstruction putting vertical dancing in the common ancestor.

Options

Six things we could build

Each is scoped to what this hardware can actually do. The first two need nothing but a laptop and an afternoon.

Recommended first

Repertoire mapper

Stream a species from alp-data, embed every clip with esp_aves2_sl_beats_all, mean-pool, then UMAP and cluster. You get a map of call types with audio you can play back per cluster. This is the core loop behind ESP's crow and zebra-finch work, at laptop scale.

CPU · one dayavex + alp-data
Recommended first

The cheap strong baseline

Reproduce Crossing the Species Divide: cache WavLM layer activations for a small BEANS subset, train linear probes per layer, find the best layer per taxon. Then add the multi-layer attention probe from the ICASSP 2026 paper and measure the gain yourself.

CPU · one daypublishable-adjacent
Highest practical payoff

Zero-label detector

Take our own field recordings, annotate 30 seconds of one call type, and let DRASDIC find every other instance. Compare against BirdCODE's 9,422-species frame detector on the same audio. No training, no annotation budget.

CPU, short clipsdrasdic + sed
Pipeline

Denoise → detect → describe

Chain the three layers: biodenoising to clean a noisy field recording, BirdCODE or Voxaboxen to find the events, then NatureLM-audio on the HF Space to caption the interesting ones. Measure whether denoising actually improves downstream detection — nobody has published that ablation cleanly.

mostly CPUreal finding possible
Novel angle

Symbolic layer

Run ISPA over a corpus to get text strings, then apply ordinary NLP — n-gram statistics, entropy rate, sequence models — to ask whether a species' call sequences carry structure beyond the single call. Cheap, and the analysis tooling is fifty years mature.

CPUispa + pysoundgen

Sequence

How we proceed

Each phase produces something runnable, and each one decides what the next phase is about. Phase 1 is already underway.

  1. Stand up the local stack in progress

    Python 3.12 environment on the SSD, avex and alp-data installed, first embeddings extracted on CPU. Verify MPS works and measure how long 1,000 clips actually takes. Deliverable: a notebook that goes from a dataset name to a UMAP plot.

    no cloud needed

  2. Choose the question next

    Everything downstream depends on which animal and which question we care about. Options: a species with good open data (crows, gibbons, giant otters, zebra finches all have curated sets in alp-data), or our own recordings. Pick one, and the tool choices stop being abstract.

    decision, not code

  3. Baseline honestly

    Before training anything: frozen encoder + linear probe, plus the WavLM speech-transfer baseline. The DCASE 2025 result says these are hard to beat, so knowing the number keeps us from celebrating a worse model later.

    CPU

  4. Detection without annotation

    Apply DRASDIC and BirdCODE to the chosen audio. If few-shot detection is good enough, we skip the annotation phase entirely. If not, we now know exactly how much labelling Voxaboxen would need.

    CPU, patient

  5. Rent a GPU, once

    The only steps that genuinely need one: fine-tuning Voxaboxen on our own annotations, and running NatureLM-audio over a real corpus rather than one clip at a time in the Space. A single 24 GB instance for a few hours covers both.

    24 GB · hours, not weeks

  6. Give something back

    Three real routes: contribute a dataset to alp-data, submit to BioDCASE, or publish the denoising-improves-detection ablation. ESP runs a Discord and a Discourse forum, and their 2026 budget is roughly $13 M with an actively growing research team — this is a field with room in it.

    optional but cheap

Hard-won

Traps, found the hard way

This machine

  • The SSD is ExFAT. It has no symlinks, and macOS scatters ._ sidecar files that break uv's source-distribution builds and venv installs. Working recipe: python3.12 -m venv --copies with pip, and point TMPDIR at an APFS path while keeping the venv and caches on the SSD.
  • The internal drive has under 3 GB free. Set HF_HOME to the SSD before any Hugging Face download, or a single checkpoint will fill the boot disk.
  • 8 GB of unified memory rules out the 8B-parameter NatureLM backbone but is comfortable for every ~90 M encoder in the stack.

Package-name landmines

  • pip install aves installs an unrelated serial-port library. ESP's package is esp-aves.
  • pip install beans is someone else's API client. ESP's BEANS is GitHub-only.
  • biodenoising and biodenoising-inference both import as biodenoising and will collide. Install one.
  • Several research repos hard-code device = "cuda" — a one-line patch, but it will look like a broken install if you don't expect it.

Model behaviour

  • AVES embeddings change with padding — a HuBERT inheritance. Embed with batch size 1, then pad. This silently degrades results if ignored.
  • NatureLM-audio is capped at 16 kHz, so 8 kHz Nyquist: it cannot hear bats, and marine performance trails birds. Use multiband-audio for ultrasonic work.
  • The demo Space takes clips of 10 seconds or less. Longer files need the Pipeline API with sliding windows.

Where to ask

  • Discourse forum: earthspeciesproject.discourse.group — the alp-data and NatureLM threads are active.
  • Discord has run since 2021; GitHub issues on avex now cover the frozen aves repo too.
  • The interactive dataset explorer at alp-explorer.esp.dev lets you filter 34 datasets by species, ecosystem and location before downloading anything.
